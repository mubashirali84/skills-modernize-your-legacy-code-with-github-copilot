# COBOL Student Account App Test Plan

This plan captures the current COBOL behavior for stakeholder validation and
as a baseline for the Node.js migration. Unless a case says otherwise, run it
in a fresh process so the starting balance is `1000.00`. Record observed output
in **Actual Result** and set **Status (Pass/Fail)** after the expected behavior
has been agreed. Cases marked for stakeholder decisions describe behavior the
current implementation does not define or functionality it does not provide.

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
| --- | --- | --- | --- | --- | --- | --- | --- |
| TC-001 | Initial account balance | Application has just started in a fresh process. | Select option `1` (View Balance). | The displayed balance is `1000.00`. |  |  | `DataProgram` initializes its working-storage balance to `1000.00`. |
| TC-002 | View balance without changing it | Fresh process; no transactions have been made. | Select option `1` twice. | Both views display `1000.00`; viewing does not change the balance. |  |  | Covers the `TOTAL` operation and `READ` path. |
| TC-003 | Credit a positive decimal amount | Fresh process; current balance is `1000.00`. | Select option `2`; enter `125.50`; then select option `1`. | Credit confirmation shows `1125.50`; the subsequent view also shows `1125.50`. |  |  | Covers addition, `WRITE`, and read-after-write. |
| TC-004 | Debit less than the balance | Fresh process; current balance is `1000.00`. | Select option `3`; enter `250.25`; then select option `1`. | Debit confirmation shows `749.75`; the subsequent view shows `749.75`. |  |  | A successful debit subtracts the amount and saves the result. |
| TC-005 | Debit the exact balance | Fresh process; current balance is `1000.00`. | Select option `3`; enter `1000.00`; then select option `1`. | Debit is accepted and the resulting balance is `0.00`. |  |  | The code allows a debit when balance equals amount (`balance >= amount`). |
| TC-006 | Debit more than the balance | Fresh process; current balance is `1000.00`. | Select option `3`; enter `1000.01`; then select option `1`. | The app displays the insufficient-funds message and the balance remains `1000.00`. |  |  | Failed debit must not write a changed balance. |
| TC-007 | Zero-value credit | Fresh process; current balance is `1000.00`. | Select option `2`; enter `0.00`; then select option `1`. | Current implementation accepts the operation, displays credit confirmation, and leaves the balance at `1000.00`. |  |  | Stakeholders should decide whether zero-value credits should instead be rejected. |
| TC-008 | Zero-value debit | Fresh process; current balance is `1000.00`. | Select option `3`; enter `0.00`; then select option `1`. | Current implementation accepts the operation, displays debit confirmation, and leaves the balance at `1000.00`. |  |  | Stakeholders should decide whether zero-value debits should instead be rejected. |
| TC-009 | Balance shared across operations | Fresh process; current balance is `1000.00`. | Credit `125.50`; debit `25.50`; view the balance. | The final balance is `1100.00`; it reflects both transactions. |  |  | Integration check that `Operations` reads and writes the same `DataProgram` balance. |
| TC-010 | Invalid numeric menu choice | Application is displaying the menu. | Enter `0`; after the menu returns, enter `5`. | For each choice, the app displays `Invalid choice, please select 1-4.` and returns to the menu without changing the balance. |  |  | `USER-CHOICE` accepts a single numeric digit; test non-numeric menu input separately if required. |
| TC-011 | Exit the application | Application is displaying the menu. | Select option `4`. | The menu loop ends, the app displays the goodbye message, and the process terminates. |  |  | Confirms the exit branch. |
| TC-012 | Balance resets after restart | Start a fresh process and credit `125.50`. | Select option `4`; start a new process; select option `1`. | The new process displays `1000.00`; prior transactions are not retained. |  |  | Current balance is in working storage only, not persistent storage. Confirm whether this is acceptable. |
| TC-013 | Transaction amount field limit / balance overflow | Fresh process; balance is `1000.00`. | Attempt to credit `999999.99`; observe the displayed result and whether the process continues. | No overflow policy is implemented. Capture the runtime behavior; stakeholders must decide whether to reject, cap, or support this transaction before migration. |  |  | `AMOUNT` and `FINAL-BALANCE` are `PIC 9(6)V99`; the requested total exceeds the balance field's six integer digits. |
| TC-014 | Invalid or negative transaction amount | Fresh process; balance is `1000.00`. | Attempt a credit and a debit using non-numeric input, then (separately) a negative amount; observe behavior and balance. | No application-level amount validation or defined error/retry behavior exists. Record current runtime behavior; agree desired rejection and balance-preservation rules with stakeholders. |  |  | `AMOUNT` is unsigned `PIC 9(6)V99`; invalid input handling may depend on the COBOL runtime. |
| TC-015 | Student identity and multiple accounts | Application is running at the main menu. | Look for a way to identify a student, select another student, or view a separate student's balance. | No student identity, account selection, or per-student balances are available; the app manages one shared balance. |  |  | Scope gap to resolve with stakeholders for the Node.js app. |
